## 2026-11-13 — hero loop: Kling via a 16:9 frame, video path fixed before the take
The Higgsfield connector turned out to be read-only (balance, models, history, import), so no take was generated and no credits were spent. The owner renders on higgsfield.ai (or the CLI, once signed in). Kling 3.0 renders only 16:9 / 9:16 / 1:1, but the hero slot is 4:3. A 4:3 start frame would get reframed, the end frame would stop matching the start, and the loop would jump at the seam. So the refs script also renders a 16:9 frame whose centre is the 4:3 frame, and `ingest-clip.mjs --aspect 4:3` crops back. The hero's video branch had used `autoPlay={!paused}`, which neither stops a playing video nor starts a paused one, and it mounted a `<video>` under reduced motion (against visual.md). Now: play via IntersectionObserver, poster `<img>` with no `<video>` when paused, `object-fit: cover`. The frame's dark vignette was retuned to the page green measured behind the stage (edge delta 23 → ≤4 levels), because it showed as a dark box on the page. The prompt stays word for word per the owner.
